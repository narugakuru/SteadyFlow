## Purpose

定义 dashboard 能力的业务约束与验收标准。

## Requirements

### Requirement: 总资产概览

总览页中的数值 SHALL 使用统一格式化函数：

- 总资产金额：使用 `formatAmount()` 格式化
- 各类别金额：使用 `formatAmount()` 格式化
- 百分比：使用 `formatPercent()` 格式化

#### Scenario: 总资产整数

- **WHEN** 总资产为 272000
- **THEN** 显示为 `¥272,000`

#### Scenario: 总资产有小数

- **WHEN** 总资产为 272000.5
- **THEN** 显示为 `¥272,000.5`

### Requirement: 总览当前盈亏快照

系统 SHALL 在总览核心资产区域展示账户总盈亏信息，至少包含账户总盈亏金额与账户总盈亏百分比。账户总盈亏金额 MUST 使用现有 `totalPnl = realizedPnl + unrealizedPnl` 口径实时计算，不得作为独立持久化字段存储。账户总盈亏百分比 MUST 作为当前快照指标展示，计算基准为 `estimatedPrincipalCny = totalAssetCny - totalPnl`。当基准无效或小于等于 0 时，百分比 MUST 显示为 `--`。

#### Scenario: 总览核心区展示账户总盈亏

- **WHEN** 用户打开 Dashboard 且总资产数据加载完成
- **THEN** 总览核心区显示账户总盈亏金额与账户总盈亏百分比

#### Scenario: 账户总盈亏实时计算

- **WHEN** 当前用户持仓盈亏为 `8000`，了结盈亏为 `3500`
- **THEN** 页面展示账户总盈亏为 `11500`

#### Scenario: 无交易或无持仓时显示

- **WHEN** 当前用户没有卖出交易且没有浮动盈亏
- **THEN** 账户总盈亏金额显示为 `0`，账户总盈亏百分比按有效分母计算或显示为 `--`

#### Scenario: 当前总盈亏百分比

- **WHEN** `totalAssetCny=110000` 且 `totalPnl=10000`
- **THEN** 总览页显示账户总盈亏百分比约为 `10%`

#### Scenario: 盈亏百分比分母无效

- **WHEN** `totalAssetCny - totalPnl <= 0`
- **THEN** 账户总盈亏百分比显示为 `--`

### Requirement: 总览资产趋势图

总览页 SHALL 在首屏核心区域展示 Wealthfolio 风格的绿色填充资产趋势图，并保持原有白色浅色主题与既有配色。该图表 MUST 使用现有净值历史图表数据作为资产价值趋势来源，并明确表示资产曲线而非历史盈亏、TWR、IRR 或投资业绩曲线。图表可使用稍深绿色线条与浅绿填充，但 MUST NOT 显示收益 0 水平线。图表下方 SHALL 提供时间范围切换控件，范围 MUST 包含：`7d`、`30d`、`90d`、`1y`、`3y`、`all`。当本地不存在有效范围偏好时，系统 MUST 默认选择 `30d`。

#### Scenario: 展示资产趋势图

- **WHEN** 用户打开总览页且净值历史存在至少两个图表点
- **THEN** 页面展示绿色填充的资产趋势图，走势基于净值历史总资产数据

#### Scenario: 数据不足时兜底

- **WHEN** 净值历史图表数据少于两个点
- **THEN** 总览图表区域显示当前资产摘要和空状态，不绘制误导性趋势线

#### Scenario: 切换图表范围

- **WHEN** 用户在总览图表下方切换到 `1y`
- **THEN** 页面使用 `GET /api/netvalue/chart?range=1y` 的数据刷新资产趋势图

#### Scenario: 首次进入默认 30d

- **WHEN** 用户首次打开总览页且本地不存在有效图表范围偏好
- **THEN** 总览资产趋势图默认选择 `30d` 并请求 `GET /api/netvalue/chart?range=30d`

#### Scenario: 切换到 7d 图表范围

- **WHEN** 用户在总览图表下方切换到 `7d`
- **THEN** 页面使用 `GET /api/netvalue/chart?range=7d` 的数据刷新资产趋势图

#### Scenario: 不显示收益零线

- **WHEN** 用户查看总览资产趋势图
- **THEN** 图表不显示收益 0 水平线，也不将资产曲线标记为收益曲线

### Requirement: 总览图表范围偏好本地持久化

系统 SHALL 将总览资产趋势图最近选择的时间范围持久化到浏览器本地存储。该偏好 MUST 不写入数据库；用户刷新页面或重新进入总览页后，系统 MUST 恢复最近一次有效选择。若本地值缺失或无效，系统 MUST 回退为 `30d`。

#### Scenario: 刷新后恢复最近图表范围

- **WHEN** 用户在总览页将资产趋势图范围切换到 `7d`，随后刷新页面
- **THEN** 总览资产趋势图继续选中 `7d`，而不是回退到 `30d`

#### Scenario: 无效本地值回退 30d

- **WHEN** 浏览器本地存储中的总览图表范围不是 `7d`、`30d`、`90d`、`1y`、`3y` 或 `all`
- **THEN** 系统忽略该值并使用 `30d`

### Requirement: Dashboard 总览支持全局显示货币

系统 SHALL 将 Dashboard/总览操作区中的货币下拉作为全站统一的显示货币控制入口，并把当前选择持久化到浏览器本地存储。该状态 MUST 不写入数据库；用户在 Dashboard 选择“默认 / USD / CNY / HKD”后，Dashboard、账户页、交易页的金额展示 MUST 共享同一状态。`默认` 的语义 MUST 为“显示记录原始币种金额”，而不是统一折算为 CNY。

#### Scenario: 首次进入页面默认使用原币视图

- **WHEN** 用户首次进入网站，且本地存储中不存在有效的显示货币偏好
- **THEN** Dashboard 的货币下拉默认选中“默认”，页面金额按各记录原始币种展示

#### Scenario: 刷新后恢复最近一次显示货币选择

- **WHEN** 用户在 Dashboard 将货币下拉切换到 USD，随后刷新页面或重新进入网站
- **THEN** Dashboard 继续显示 USD 为当前选中项，而不是回退到默认

#### Scenario: Dashboard 修改后账户页跟随

- **WHEN** 用户在 Dashboard 将货币下拉切换到 HKD，然后进入账户页
- **THEN** 账户页金额展示按 HKD 实时换算显示，无需用户再次设置

### Requirement: 资产配置纪律表

系统 SHALL 在 Dashboard 中显示资产配置纪律表。桌面端纪律表 MUST 不显示顶层表头，资产类别汇总条本身作为主列表行。汇总条 MUST 使用两行高行高布局：左侧显示大字加粗资产类别名称，中间显示加大尺寸的实际/目标进度条，右侧第一行显示大字加粗市值，第二行显示持仓盈亏金额+比例；汇总条的“市值”语义 MUST 替代旧“金额”语义。资产类别汇总条点击 SHALL 继续负责展开/收起。展开后的桌面端标的明细 MUST 在该资产类别内部显示不显眼的六列表头：标的、份额、现价、成本价、市值、盈亏；每个标的行 MUST 是单行数据行，标的列 MUST 将股票名称、股票代码和账户标签放在同一行，份额、现价、成本价、市值、盈亏等数据列 MUST 右对齐并整体向右侧聚集。移动端展开明细 MUST 使用卡片式标的条，不得渲染为桌面数据表。系统 MUST 删除纪律表状态/操作列，且主列表中不显示状态 badge、调仓建议或直接操作按钮。非现金类别显示汇总持仓盈亏金额及颜色标识，现金类别持仓盈亏列显示"--"。标的条点击 SHALL 打开持仓详情 Drawer，Drawer 中提供份额、成本价、占比、买入、卖出和编辑入口。编辑弹窗 SHALL 区分 amount/shares 估值模式，shares 模式使用三字段联动编辑。

#### Scenario: 纪律表主列表不显示顶层表头

- **WHEN** 用户在桌面端查看 Dashboard 纪律表
- **THEN** 纪律表主列表不显示“资产类别 / 参考指标 / 市值 / 持仓盈亏”顶层表头，直接展示资产类别汇总条

#### Scenario: 汇总条显示市值而非金额

- **WHEN** 用户查看纪律表资产类别汇总条
- **THEN** 汇总条对应核心金额语义为“市值”，展示该资产类别当前市值

#### Scenario: 汇总条使用两行大行高布局

- **WHEN** 用户在桌面端查看资产类别汇总条
- **THEN** 左侧资产类别为大字加粗，中间进度条尺寸加大，右侧第一行显示大字加粗市值，第二行显示持仓盈亏金额和比例

#### Scenario: 纪律表汇总条展开收起

- **WHEN** 用户点击某个资产类别汇总条
- **THEN** 系统展开或收起该资产类别下的标的列表

#### Scenario: 桌面端展开持仓使用六列明细表

- **WHEN** 用户在桌面端展开某资产类别查看持仓
- **THEN** 该资产类别内部显示不显眼的表头“标的、份额、现价、成本价、市值、盈亏”，每个标的行按同一六列排列

#### Scenario: 纪律表桌面持仓行匹配账户页信息模型

- **WHEN** 用户查看桌面端展开的纪律表标的行
- **THEN** 标的列在同一行显示股票名称、股票代码和账户标签，市值列显示带币种的突出金额，盈亏列显示持仓盈亏金额和比例

#### Scenario: 纪律表桌面持仓行单行右聚集

- **WHEN** 用户查看桌面端展开的纪律表标的行
- **THEN** 整个标的行数据保持在同一行，份额、现价、成本价、市值和盈亏列右对齐并偏向右侧聚集

#### Scenario: 移动端展开持仓保持卡片

- **WHEN** 用户在移动端展开某资产类别查看持仓
- **THEN** 标的明细以移动端卡片展示，不显示桌面六列表格行

#### Scenario: 现金类别持仓盈亏显示

- **WHEN** 纪律表展示现金类别
- **THEN** 持仓盈亏列显示"--"

#### Scenario: 纪律表不显示状态操作列

- **WHEN** 用户查看纪律表桌面端或移动端
- **THEN** 主列表不显示状态列、状态 badge、调仓建议或直接操作按钮

#### Scenario: 纪律表持仓详情 Drawer

- **WHEN** 用户点击纪律表中的某个非现金标的条
- **THEN** 系统打开该标的的持仓详情 Drawer，展示份额、现价、成本价、市值、占比、持仓盈亏和备注等详情

#### Scenario: 纪律表持仓买入

- **WHEN** 用户在持仓详情 Drawer 点击“买入”
- **THEN** 弹出 TransactionForm，交易类型为买入，并自动预填该持仓所属账户和持仓信息

#### Scenario: 纪律表持仓卖出

- **WHEN** 用户在持仓详情 Drawer 点击“卖出”
- **THEN** 弹出 TransactionForm，交易类型为卖出，并自动预填该持仓所属账户和持仓信息

#### Scenario: 纪律表编辑 shares 模式持仓

- **WHEN** 用户在持仓详情 Drawer 点击 shares 模式持仓的“编辑”
- **THEN** 弹出编辑 Dialog，显示股价/份额/市值三字段联动编辑，用户改任意字段，系统根据"最后两次编辑锁定"规则自动计算第三个字段

#### Scenario: 纪律表编辑 amount 模式持仓

- **WHEN** 用户在持仓详情 Drawer 点击 amount 模式持仓的“编辑”
- **THEN** 弹出编辑 Dialog，显示名称、市值、资产类别字段

### Requirement: Dashboard 纪律表支持类别内明细三态排序

系统 SHALL 允许用户通过 Dashboard 纪律表中的“市值”与“持仓盈亏”排序控件，对每个资产类别展开后的明细列表进行临时排序。排序状态 MUST 按 `降序 -> 升序 -> 默认` 循环；其中“默认” MUST 恢复为后端返回的数据库手动排序顺序。排序比较前 MUST 先将不同币种市值与盈亏折算为统一货币后再比较。排序作用域 MUST 限定在单个资产类别内部，资产类别顶层顺序不得被打乱。

#### Scenario: 首次点击市值按类别内市值降序

- **WHEN** 用户点击纪律表中的“市值”排序控件，且此前未启用该字段排序
- **THEN** 每个资产类别展开后的明细列表均按各自市值从大到小排序，资产类别顶层顺序保持不变

#### Scenario: 第二次点击同一字段按升序

- **WHEN** 用户已经启用“持仓盈亏”的降序排序后再次点击同一控件
- **THEN** 每个资产类别展开后的明细列表改为按各自持仓盈亏从小到大排序，资产类别顶层顺序仍保持不变

#### Scenario: 第三次点击恢复数据库默认顺序

- **WHEN** 用户已经启用某个纪律表字段的升序排序后第三次点击同一控件
- **THEN** 每个资产类别展开后的明细列表恢复为数据库返回的默认手动顺序

#### Scenario: 跨币种持仓按统一货币比较

- **WHEN** 同一资产类别下同时存在 CNY、USD、HKD 持仓，且用户启用市值或持仓盈亏排序
- **THEN** 系统先将这些持仓折算到统一货币后再比较顺序，而不是直接按原币数字排序

### Requirement: Dashboard 纪律表排序偏好本地持久化

系统 SHALL 将 Dashboard 纪律表当前使用的排序字段与方向持久化到本地存储。用户刷新页面或重新进入网站后，纪律表 MUST 恢复为最近一次保存的本地排序偏好；若本地没有有效偏好，则 MUST 使用数据库默认顺序。

#### Scenario: 刷新后恢复最近排序偏好

- **WHEN** 用户已在纪律表中启用“金额降序”或“持仓盈亏升序”，随后刷新页面
- **THEN** 页面重新加载后纪律表仍使用刷新前的同一排序字段与方向

#### Scenario: 本地无有效偏好时回退默认顺序

- **WHEN** 用户首次进入 Dashboard，或本地存储中不存在有效纪律表排序偏好
- **THEN** 纪律表按数据库默认顺序展示明细列表，不启用临时排序高亮

### Requirement: Dashboard 桌面端纪律表表头显示排序状态

系统 SHALL 在 Dashboard 桌面端纪律表展开后的每个资产类别持仓明细表头中，为“市值”与“盈亏”显示轻量排序状态。默认态图标与文字 MUST 使用弱化颜色；激活态 MUST 与当前方向箭头一起高亮。Dashboard 桌面端纪律表 MUST NOT 通过顶层主表头承载排序状态。

#### Scenario: 桌面端无顶层排序表头

- **WHEN** 用户在桌面端查看未展开或已展开的纪律表
- **THEN** 纪律表不显示顶层主表头，也不在顶层主表头中显示排序状态

#### Scenario: 展开明细表头默认态显示静止箭头

- **WHEN** 用户在桌面端展开某资产类别且未启用临时排序
- **THEN** 该类别明细表头中的“市值”与“盈亏”使用弱化默认态显示排序提示

#### Scenario: 展开明细表头激活态显示方向高亮

- **WHEN** 用户已经启用纪律表“市值”或“持仓盈亏”的降序或升序排序
- **THEN** 展开明细表头中的对应字段文字与当前方向箭头高亮显示，另一个字段保持默认态

### Requirement: Dashboard 布局

系统 SHALL 调整 Dashboard/总览布局为：资产趋势图核心区域 + 图表时间范围控件 + 资产配置纪律表（含可展开的类别详情）+ 再平衡建议。所有数据 MUST 限定为当前用户的数据。Dashboard 默认不再展示资产分布饼图，不显示账户列表，不显示市场页内容，不显示股价更新页内容。

#### Scenario: Dashboard 默认展示

- **WHEN** 已登录用户打开 Dashboard（/）
- **THEN** 页面从上到下依次显示：资产趋势图核心区域、时间范围控件、资产配置纪律表、再平衡建议。不显示资产分布饼图，不显示账户列表，不显示其他用户的数据

### Requirement: Dashboard 缓存优先展示与条件刷新

Dashboard 页面 SHALL 使用全局客户端缓存层读取资产配置数据，并遵循统一时效策略：`staleTime=60s`、`persistTime=3d`。在持久化失效前，缓存数据 MUST 优先展示给用户。

#### Scenario: Dashboard 60秒内命中缓存

- **WHEN** 用户进入 Dashboard 且命中缓存，缓存年龄小于或等于 60 秒
- **THEN** 页面立即展示缓存数据，且不触发异步远端刷新

#### Scenario: Dashboard 60秒后命中缓存

- **WHEN** 用户进入 Dashboard 且命中缓存，缓存年龄大于 60 秒且小于 3 天
- **THEN** 页面先展示缓存数据，再异步请求远端数据并更新页面数值

#### Scenario: Dashboard 持久化缓存过期

- **WHEN** 用户进入 Dashboard 且缓存年龄大于或等于 3 天
- **THEN** 页面不使用过期缓存作为命中数据，按远端请求流程加载

### Requirement: Dashboard 后台刷新失败提示

Dashboard 在已展示缓存数据的前提下，若后台刷新失败 SHALL 显示全局失败通知条，通知条 MUST 自动缓慢淡出消失，且页面保持当前可用数据。

#### Scenario: Dashboard 异步刷新失败

- **WHEN** Dashboard 已展示缓存数据且后台请求失败
- **THEN** 显示“更新数据失败”通知条，随后自动缓慢消失，并继续保留当前缓存展示

### Requirement: Dashboard 使用 LoadingSpinner 加载动画

Dashboard 页面 SHALL 在数据加载期间使用 `LoadingSpinner` 组件替代纯文本"加载中..."，但仅在“无可用缓存且远端数据尚未返回”时展示全页加载动画。

#### Scenario: Dashboard 无缓存时加载中

- **WHEN** Dashboard 页面正在获取资产配置数据，且本地无可用缓存
- **THEN** 页面显示 LoadingSpinner 组件（带"加载中..."文字），替代原有纯文本

#### Scenario: Dashboard 有缓存时进入页面

- **WHEN** Dashboard 页面存在未过 `persistTime` 的本地缓存
- **THEN** 页面优先显示缓存数据，不进入全页 LoadingSpinner 阶段

### Requirement: Dashboard 导航

系统 SHALL 在 Dashboard/总览核心区域提供必要的“货币视图”下拉框与「更新股价」按钮；下拉框 MUST 放置在「更新股价」按钮附近，并固定提供“默认、USD、CNY、HKD”四个选项。系统 MUST 不显示「记录净值」手动按钮，也不得恢复独立的“股价更新”页面入口。点击「更新股价」后调用 `POST /api/holdings/fetch-prices` 的手动模式，显示加载状态，完成后展示逐条结果明细弹窗并刷新页面数据。完整数据导出入口 MUST 放置在设置面板中，而不是 Dashboard header。

#### Scenario: Dashboard 操作入口

- **WHEN** 用户打开 Dashboard
- **THEN** 总览核心区域显示货币视图下拉框和「更新股价」按钮，不显示「记录净值」按钮，不显示完整数据导出按钮，也不显示“股价更新”页面入口

#### Scenario: 货币视图下拉显示固定选项

- **WHEN** 用户展开 Dashboard header 的货币下拉框
- **THEN** 下拉框显示“默认、USD、CNY、HKD”四个选项

#### Scenario: 点击手动更新股价

- **WHEN** 用户在 Dashboard 点击「更新股价」按钮
- **THEN** 按钮显示加载状态，调用手动模式报价同步接口，完成后弹出逐条明细结果并刷新页面资产数据

#### Scenario: 不跳转股价更新页

- **WHEN** 用户在 Dashboard/总览触发手动报价刷新
- **THEN** 系统留在当前总览页，不跳转到 `/batch-update`

### Requirement: Dashboard 股价更新时间提示

系统 SHALL 在总资产卡片区域展示一个不显眼的股价更新时间提示，用于表达最近一次成功报价同步时间。该提示 MUST 与前端查询缓存时间区分，不得复用纯前端 `DataFreshness` 语义。

#### Scenario: 展示最近成功同步时间

- **WHEN** 当前用户存在最近一次成功报价同步记录
- **THEN** 总资产卡片显示“股价更新：<最近成功时间或相对时间>”的弱提示

#### Scenario: 尚无成功同步记录

- **WHEN** 当前用户从未成功同步过股价
- **THEN** 总资产卡片显示“股价更新：暂未成功同步”或等效弱提示文案

### Requirement: Dashboard 静默报价兜底刷新

Dashboard 在数据加载完成后 SHALL 判断股价数据是否超过陈旧阈值；若已超过阈值且当前不存在进行中的报价同步，则页面 MUST 自动触发一次静默报价刷新。静默刷新 MUST 不弹出逐条结果明细弹窗，但完成后 MUST 刷新页面资产数据与股价更新时间提示。

#### Scenario: 进入 Dashboard 时数据已过期

- **WHEN** 用户打开 Dashboard，且最近一次成功报价同步已超过系统设定的陈旧阈值
- **THEN** 页面自动触发一次静默报价刷新，不弹出结果弹窗，并在完成后刷新资产数据与股价更新时间提示

#### Scenario: 进入 Dashboard 时数据仍新鲜

- **WHEN** 用户打开 Dashboard，且最近一次成功报价同步尚未超过陈旧阈值
- **THEN** 页面不触发静默报价刷新

#### Scenario: 已有进行中的报价同步

- **WHEN** 用户打开 Dashboard 时系统判断已有进行中的报价同步
- **THEN** 页面不再重复发起第二次静默报价刷新

### Requirement: Dashboard 持仓精简导出按钮

系统 SHALL 在 Dashboard 的“资产配置纪律”标题区域提供“导出持仓”按钮。该按钮 MUST 复用 Dashboard“更新股价”一致的主按钮配色。点击后 MUST 下载精简决策快照，仅包含总资产盈亏摘要、各类资产占比和非零市值标的持仓。

#### Scenario: 资产配置纪律区域显示按钮

- **WHEN** 用户打开 Dashboard
- **THEN** “资产配置纪律”标题区域显示“导出持仓”按钮，且按钮样式与“更新股价”保持一致

#### Scenario: 点击导出持仓

- **WHEN** 用户点击“导出持仓”按钮
- **THEN** 系统下载精简决策快照，不包含 `raw` 与 `accountBreakdown`

### Requirement: Dashboard 纪律区快捷交易按钮

系统 SHALL 在 Dashboard 的“资产配置纪律”标题区域提供一个“交易”按钮，并将其放置在“导出持仓”按钮左侧。点击后 MUST 打开通用交易弹窗，默认交易类型为买入，且默认不选择账户与持仓。

#### Scenario: 纪律区显示交易按钮

- **WHEN** 用户打开 Dashboard
- **THEN** “资产配置纪律”标题区域显示“交易”按钮，位置在“导出持仓”按钮左侧

#### Scenario: 点击交易按钮打开空上下文表单

- **WHEN** 用户点击 Dashboard 纪律区的“交易”按钮
- **THEN** 系统打开交易弹窗，默认类型为“买入”，账户选择器与持仓选择器均保持为空，等待用户手动选择
