## Purpose

定义 discipline-notes 能力的业务约束与验收标准。

## Requirements

### Requirement: 全局悬浮笔记入口

系统 SHALL 在登录后的任意业务页面右下角提供一个仅图标显示的圆形悬浮笔记入口，不显示文字标签。该入口 MUST 固定定位并在页面滚动时保持可见。入口层级 SHALL 高于普通页面内容且低于 Dialog/Sheet 等模态弹层，以确保在其他弹窗出现时被遮挡而不抢占交互焦点。

#### Scenario: 任意页面可访问笔记入口

- **WHEN** 用户在 Dashboard、账户页、交易页、净值页或市场页浏览内容
- **THEN** 右下角均显示同一个圆形笔记图标入口

#### Scenario: 模态弹窗优先级高于笔记入口

- **WHEN** 用户打开编辑持仓或交易等 Dialog
- **THEN** 笔记悬浮入口被该 Dialog 遮挡且不阻挡弹窗交互

### Requirement: 笔记中心弹窗结构

用户点击悬浮入口后，系统 SHALL 打开居中的大弹窗作为笔记中心。桌面端主编辑区从上到下 MUST 呈现标题输入、正文内容区与底部经典句子提示，不得再额外显示“投资笔记”“标题”“笔记内容”等说明性标签。经典句子 MUST 从前端本地数组中随机抽取，且展示时 MUST NOT 依赖数据库中已保存的 `quote` 字段作为真值。桌面端当前选中笔记的删除操作 MUST 以红色垃圾桶图标按钮呈现，并放在标题行右侧。

#### Scenario: 桌面端打开笔记中心时聚焦标题与正文

- **WHEN** 用户在桌面端点击右下角圆形笔记入口
- **THEN** 系统打开大弹窗，右侧主编辑区直接显示标题输入与正文内容区，不展示“投资笔记”“标题”“笔记内容”等辅助说明标签

#### Scenario: 经典句子来自本地随机数组

- **WHEN** 用户打开笔记中心或切换当前查看的笔记
- **THEN** 系统展示的经典句子来自前端本地数组的随机抽取结果，而不是读取该笔记已保存的数据库 quote 内容

#### Scenario: 桌面端删除入口使用红色垃圾桶图标

- **WHEN** 用户在桌面端查看已选中的投资笔记
- **THEN** 标题行右侧显示与账户页危险操作风格一致的红色垃圾桶图标按钮，用户可通过该按钮删除当前笔记

### Requirement: 笔记中心弹窗尺寸与滚动区域稳定

系统 SHALL 为笔记中心弹窗提供稳定的视口级布局骨架。桌面端在阅读模式与编辑模式之间切换时 MUST 复用同一套大尺寸弹窗高度与宽度约束，不得因模式切换而明显变窄、变矮或跳动；右侧正文区域 MUST 保持“上部编辑、底部句子”的垂直结构。移动端 MUST 采用占满可视区域的全屏式布局，且 MUST 将当前笔记编辑区放在上方，将便签列表放在屏幕下方；标题输入、正文区域与经典句子提示 MUST 按顺序出现在上方编辑区内。弹窗外层容器 MUST 保持固定，便签列表与正文内容 MUST 使用各自的内部滚动容器；正文滚动条 SHALL 位于正文阅读框或编辑框内部，滚动时不得带动整个弹窗主体内容一起移动。

#### Scenario: 桌面端切换阅读与编辑模式时尺寸稳定

- **WHEN** 用户在桌面端打开一条投资笔记，并在阅读模式和编辑模式之间切换
- **THEN** 笔记弹窗保持同一套大尺寸骨架，正文区域尺寸不因模式切换而跳动，经典句子仍固定在主编辑区底部

#### Scenario: 移动端优先展示当前笔记编辑区

- **WHEN** 用户在移动端打开投资笔记弹窗
- **THEN** 弹窗占满当前可视区域，标题输入、正文区域与经典句子先显示在上方，便签列表显示在屏幕下方

#### Scenario: 正文滚动不带动整个弹窗

- **WHEN** 用户查看或编辑超出可视高度的长笔记内容并上下滚动
- **THEN** 只有正文阅读框或编辑框内部内容滚动，弹窗标题、外围容器与其他固定区块保持稳定

### Requirement: 多条便签式笔记管理

系统 SHALL 支持用户自由创建、查看、编辑、删除多条笔记。每条笔记 MUST 至少包含标题、交易计划和 Markdown 内容。笔记数据 MUST 按 userId 隔离，用户只能访问自己的笔记。

#### Scenario: 创建多条笔记

- **WHEN** 用户连续创建两条不同标题的笔记
- **THEN** 两条笔记均被保存并可在笔记中心切换查看

#### Scenario: 删除单条笔记

- **WHEN** 用户删除某条已存在笔记
- **THEN** 系统仅删除目标笔记，其他笔记保持不变

#### Scenario: 用户数据隔离

- **WHEN** 用户 A 与用户 B 分别进入笔记中心
- **THEN** 双方只看到各自创建的笔记数据

### Requirement: Markdown 内容渲染

系统 SHALL 对笔记内容提供 Markdown 渲染显示能力，并保留原始 Markdown 文本用于编辑。渲染器 MUST 禁用原始 HTML 直出，防止脚本注入。

#### Scenario: Markdown 语法正常渲染

- **WHEN** 用户输入 `## 交易计划`、`- 分批买入`、`**纪律执行**`
- **THEN** 预览区域按对应标题、列表和加粗样式渲染

#### Scenario: HTML 标签不执行

- **WHEN** 用户在内容中输入 `<script>alert(1)</script>`
- **THEN** 渲染结果不执行脚本，页面保持安全

### Requirement: 笔记编辑失焦自动保存

系统 SHALL 移除笔记编辑中的显式“保存”按钮。当前选中笔记的标题或正文被修改后，当用户离开当前笔记编辑上下文时 MUST 自动保存，包括关闭正文编辑态、切换到其他笔记、关闭弹窗或焦点离开当前笔记编辑区域。若保存失败，系统 MUST 保留未提交内容并提示失败，不得静默丢失用户输入。

#### Scenario: 退出编辑态后自动保存

- **WHEN** 用户修改当前笔记正文后离开编辑态
- **THEN** 系统自动保存该笔记，无需点击额外保存按钮

#### Scenario: 切换笔记前先保存当前修改

- **WHEN** 用户修改当前笔记后点击另一条笔记
- **THEN** 系统先保存当前笔记的修改，再切换到目标笔记内容

#### Scenario: 自动保存失败时保留草稿

- **WHEN** 用户修改笔记后触发自动保存，但保存请求失败
- **THEN** 系统保留用户刚刚输入的标题或正文，并显示保存失败提示
