## Why

当前净值记录仍依赖 Dashboard 上的“记录净值”手动按钮，且记录日期基于服务器默认时区，无法满足“账户信息变动后自动刷新净值”和“按用户时区每天稳定记录一次”的需求。随着多用户使用增加，需要把净值记录从手动触发改为系统自动触发，并提供可配置时区与固定日更调度。

## What Changes

- 移除 Dashboard 顶部“记录净值”按钮与对应手动触发入口，避免重复心智负担。
- 在资产相关写操作成功后自动触发“记录当日净值”（统一封装调用），覆盖账户、持仓、交易、批量改价等会影响总资产的接口。
- 为净值记录引入“用户时区”概念：支持用户手动设置时区，默认 `Asia/Shanghai`。
- 当日净值日期计算改为基于用户时区，确保跨时区用户“当天”定义正确。
- 新增每日定时自动记录机制：每天凌晨 3:00（按用户时区）自动为每位用户记录/刷新当日净值。
- 保留 `(userId, date)` 唯一约束与 upsert 语义，同日多次触发只覆盖不新增。

## Capabilities

### New Capabilities

- None

### Modified Capabilities

- `daily-netvalue`: 从“首次打开自动记录 + 手动刷新”升级为“写操作自动触发 + 用户时区 + 每日 3:00 定时记录”。
- `dashboard`: 头部操作区移除“记录净值”按钮，仅保留与净值自动化无冲突的操作入口。

## Impact

- 前端页面：`/` Dashboard 头部按钮与相关事件处理。
- 后端 API：账户/持仓/交易/批量更新相关 mutation 路由在成功后接入统一净值触发封装。
- 净值服务：抽取可复用的净值记录服务函数（统一日期计算、upsert、错误处理）。
- 设置系统：新增/复用用户设置项保存时区（默认 `Asia/Shanghai`）。
- 定时系统：新增每日定时任务入口（cron）并安全校验，支持批量触发用户当日净值记录。
