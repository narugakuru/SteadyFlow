## MODIFIED Requirements

### Requirement: HoldingRow 移动端垂直布局

HoldingRow SHALL 在移动端（<768px）使用高密度信息卡片布局，确保名称、市值、占比、盈亏、价格/份额明细和操作入口全部可见可操作。卡片头部 MUST 显示资产信息和 `...` 菜单触发器；核心数据区 MUST 突出展示持仓总金额和占总资产比；明细数据区 MUST 以紧凑网格展示盈亏、价格和份额等次要数据。移动端 HoldingRow MUST 使用轻量 `...` 菜单承载买入、卖出和编辑操作，MUST NOT 使用底部抽屉承载这些持仓操作。`...` 触发器的实际可点击热区 MUST 不小于 44x44 像素。

#### Scenario: 移动端持仓卡片显示

- **WHEN** 用户在移动端查看持仓行
- **THEN** 持仓信息以卡片结构展示：头部显示名称、代码/标签和 `...` 菜单，核心区显示市值和占比，明细区显示盈亏、价格和份额等信息

#### Scenario: 移动端持仓操作菜单

- **WHEN** 用户在移动端点击 HoldingRow 的 `...` 菜单
- **THEN** 系统在当前位置展示轻量操作菜单，提供买入、卖出和编辑操作，不从底部弹出抽屉

#### Scenario: 移动端菜单触发热区

- **WHEN** 用户在移动端查看 HoldingRow 的 `...` 操作入口
- **THEN** 触发器视觉上保持紧凑，但实际可点击热区不小于 44x44 像素

#### Scenario: 桌面端持仓行使用数据网格

- **WHEN** 用户在桌面端查看 HoldingRow
- **THEN** 持仓行使用单行数据网格展示，数字列保持右对齐
