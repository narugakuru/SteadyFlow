## Context

当前项目已具备基础移动端适配能力，但批量更新页与多类弹窗在小屏下仍存在局部破版和可触达性不足问题。与此同时，资产类别在历史实现中存在“股票基金”与“股票”并存、以及排序不一致的问题，导致不同页面认知割裂。

本次变更覆盖 `mobile-responsive`、`batch-update`、`asset-allocation`、`navigation-layout` 四个既有能力，目标是在不引入新依赖的前提下完成统一行为约束，并保持桌面端既有体验稳定。

## Goals / Non-Goals

**Goals:**

- 统一移动端弹窗边界，确保弹窗不超出手机可视范围，内容可滚动。
- 提升弹窗关闭按钮触控可用性，避免小屏误触或难以点击。
- 修复批量更新页移动端布局崩坏，确保列表、输入与操作按钮可读可操作。
- 全局统一资产类别文案为“股票、黄金、债券、现金”，并固定默认排序。
- 移除页面内冗余“返回dashboard”按钮，统一依赖全局导航。
- 点击SteadyFlow就是回到总览界面

**Non-Goals:**

- 不调整资产类别动态化机制（仍基于用户配置数据）。
- 不引入新的 UI 组件库或重构现有导航信息架构。
- 不改变桌面端弹窗视觉风格，仅在移动端增加约束。

## Decisions

### 1) 移动端弹窗统一使用 viewport-safe 约束

- 决策：在移动端为 Dialog Content 统一设置 `w-full max-w-none max-h-[100dvh] overflow-y-auto`，并结合安全区内边距（如 `pb-[env(safe-area-inset-bottom)]`）避免底部遮挡。
- 原因：`100dvh` 比 `vh` 更适配移动浏览器动态工具栏，能减少视觉溢出和跳动。
- 备选方案：
  - 继续使用固定 `85vh`：在部分机型可用，但复杂表单场景仍容易超出且可视内容不足。
  - 全部改为 Sheet：改动面过大，会影响既有桌面/移动统一组件复用。

### 2) 关闭按钮采用最小触控热区标准

- 决策：移动端弹窗关闭按钮最小可点击区域提升到 44x44（或等效 Tailwind 尺寸），并固定在顶部可见区域。
- 原因：符合移动端触控基本可用性标准，降低误触和关闭困难。
- 备选方案：
  - 保持现有小图标按钮：实现最少但可用性风险高。

### 3) 批量更新页移动端布局改为单列优先

- 决策：小屏下将批量更新行布局切换为单列/分段信息块，关键操作按钮固定在可见区域附近，避免横向拥挤导致换行错位。
- 原因：批量更新页信息密度高，桌面表格式在移动端易崩坏；单列结构更稳健。
- 备选方案：
  - 维持表格并增加横向滚动：可实现但编辑输入与操作按钮体验差。

### 4) 资产类别文案与排序在展示层做统一归一

- 决策：前后端展示逻辑统一将“股票基金”映射为“股票”，并在纪律表、配置项、选择器中应用固定顺序“股票、黄金、债券、现金”。
- 原因：减少历史命名差异带来的认知负担，确保各页面一致。
- 备选方案：
  - 仅改部分页面文案：实现快但会继续出现跨页不一致。

### 5) 去除页面内“返回总览”按钮

- 决策：移除业务页面内部“返回总览”按钮，保留并依赖顶部全局导航（含移动端抽屉导航）。
- 原因：避免重复导航入口，减轻页面噪音并统一交互路径。
- 备选方案：
  - 继续保留按钮：对少量用户有帮助，但长期造成交互冗余。

## Risks / Trade-offs

- [Risk] 旧数据或文案残留“股票基金”导致局部显示不一致 -> Mitigation: 增加统一映射函数并在关键列表做回归检查。
- [Risk] 不同移动设备对 `dvh` 支持存在差异 -> Mitigation: 保留 `max-h-screen` 作为兜底类并做主流设备测试。
- [Risk] 批量更新页布局调整可能影响桌面效率 -> Mitigation: 严格限定 `md` 断点以下生效，桌面布局不变。
- [Risk] 去除返回按钮后用户路径改变 -> Mitigation: 确保导航栏在所有页面始终可见且当前页高亮明确。
