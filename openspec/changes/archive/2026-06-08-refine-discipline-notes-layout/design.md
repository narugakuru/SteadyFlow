## Context

当前纪律投资笔记弹窗已经具备多便签、Markdown 渲染与失焦自动保存能力，但 UI 仍沿用较重的说明性文案，桌面端句子区位于顶部，移动端则先显示便签列表再进入正文。与此同时，前端会回显已保存笔记中的 `quote` 字段，导致经典句子与具体笔记记录耦合，不符合“每次本地随机抽取”的预期。

约束条件：

- 现有数据库表 `disciplineNotes.quote` 仍为非空字段，本次不引入 schema 迁移。
- 自动保存与现有 Markdown 阅读/编辑切换行为必须保持稳定。
- 桌面端与移动端都要继续维持独立滚动区，避免整窗跟随正文滚动。

## Goals / Non-Goals

**Goals:**

- 让经典句子完全由前端本地数组随机生成，不再以数据库中的 quote 作为展示真值。
- 精简桌面端主编辑区文案层级，把标题输入和正文编辑作为主视觉中心，并将句子提示下沉到底部。
- 调整移动端布局，把当前笔记编辑区放在上方，把便签列表移到底部。
- 保持现有创建、切换、自动保存和删除能力。

**Non-Goals:**

- 不删除数据库中的 `quote` 列，也不做历史数据清洗。
- 不重做整套笔记数据模型或新增独立的 quote 配置接口。
- 不修改悬浮入口、Markdown 渲染规则或自动保存触发条件。

## Decisions

### 决策 1：经典句子改为前端会话态随机值，后端仅保留兼容字段

- 决策：前端组件在弹窗打开、创建新笔记或切换笔记时，从本地 `CLASSIC_QUOTES` 数组随机挑选一句作为当前展示值；展示逻辑不再读取 `selectedNote.quote`。后端创建/更新接口仍接受 `quote`，但校验放宽为可选并在缺失时回填兼容值。
- 理由：这可以立刻实现“本地随机、与数据库解耦”的用户体验，同时避免本次为兼容历史数据发起数据库迁移。
- 备选：直接删除 `quote` 字段并修改表结构。长期更干净，但会引入迁移、历史数据兼容和多数据库同步成本，本次不采用。

### 决策 2：桌面端保留双栏骨架，但把主编辑区改成“标题/正文/句子”垂直结构

- 决策：桌面端继续使用左侧便签列表、右侧编辑区的双栏布局；右侧顶部只保留标题输入与删除图标按钮，正文区域占据主体空间，经典句子放在正文下方。
- 理由：双栏切换效率已验证有效，无需推倒重来；只需要调整信息层级即可满足当前交互诉求。
- 备选：改成单栏分页或顶部 Tab。会增加切换成本，也偏离现有稳定实现，因此不采用。

### 决策 3：移动端采用“上编辑、下列表”的堆叠布局

- 决策：在移动端将编辑区放在上半部分，按“标题输入 -> 正文区域 -> 经典句子”顺序排列；便签列表作为底部独立区域，保留新建按钮与切换能力。
- 理由：移动端单屏空间有限，优先暴露当前笔记内容比先展示列表更符合用户的主要操作路径。
- 备选：继续沿用桌面端顺序，只把列表压缩。这样仍会让内容编辑被列表挤占首屏，因此不采用。

### 决策 4：删除入口复用账户页的危险操作视觉

- 决策：删除按钮改为图标型 ghost/destructive 组合，只显示红色垃圾桶图标，不再显示“删除”文字。
- 理由：账户页已经建立了危险操作的视觉约定，直接复用能减少样式分叉。
- 备选：保留 outline 按钮并换色。视觉重量仍偏大，不符合“让编辑区更聚焦”的目标。

## Risks / Trade-offs

- [Risk] 历史笔记行仍保留旧 `quote` 值，数据库内容与前端展示不一致 -> Mitigation：将其明确视为兼容字段，不再作为任何展示真值来源。
- [Risk] 移动端重新排序区块后，可用高度变得更紧张 -> Mitigation：继续维持正文区和便签列表各自独立滚动，并限制底部列表高度。
- [Risk] 删除按钮去文字后可发现性略降 -> Mitigation：保留标准垃圾桶图标、红色危险色和 `aria-label`，与账户页保持同一语义。
