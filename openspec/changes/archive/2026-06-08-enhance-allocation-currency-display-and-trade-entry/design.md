## Context

当前资产快照服务已经同时返回三类信息：

- 总览与资产类别汇总使用的人民币基准值（`totalAssetCny`、`actualValue`、`totalPnl`、`adjustAmount`）。
- 持仓级的原币金额与人民币折算值（`marketValue` / `marketValueCny`、`pnlAmount` / `pnlAmountCny`）。
- 汇率表（当前主要是 `XXX/CNY`）。

这意味着本次多币种展示切换不需要改数据库，也不需要改写资产价格，只要在前端基于“原币金额 + CNY 基准值 + 汇率”做临时投影即可。另一方面，纪律区标题新增“交易”按钮会首次从 Dashboard 顶层直接打开通用交易弹窗，因此交易表单需要把“无上下文入口”和“持仓快捷入口”两种默认值行为区分开。

约束条件：

- 用户要求货币切换是临时视图，不持久化、不入库、刷新页面后回到默认。
- 默认视图不是“所有内容都统一为人民币”，而是“总览/类别汇总仍看人民币，持仓明细回到原币”。
- 账户页没有新增货币切换器，只需要和默认纪律视图对齐，移除多余的人民币近似值。

## Goals / Non-Goals

**Goals:**

- 在不修改数据库 schema 的前提下，为 Dashboard 增加临时货币视图切换。
- 让总资产卡片、纪律表类别汇总、持仓行、再平衡建议和饼图 tooltip 使用一致的投影规则。
- 为纪律区增加通用“交易”入口，同时保持持仓快捷交易入口的预填行为不变。
- 将资产类别汇总盈亏升级为“金额 + 收益率”，并让饼图百分比标签固定为两位小数。

**Non-Goals:**

- 不新增“主要币种”设置，也不把本次选择写入 settings。
- 不改变资产配置、偏离度和再平衡的底层计算基准；这些核心计算仍以 CNY 为统一基准完成。
- 不为账户页增加新的货币切换器。
- 不调整交易写入、副作用或盈亏核算逻辑。

## Decisions

### 1. 货币切换采用前端投影，默认视图单独定义为 `default`

- 决策：Dashboard 新增三类显示模式：
  - `default`：总览卡片、类别汇总、再平衡和饼图 tooltip 使用 CNY；持仓明细使用原币。
  - `<currency>`：总览卡片、类别汇总、持仓明细、再平衡和饼图 tooltip 统一投影到目标币种。
- 理由：这正好对应用户提出的“默认看总览人民币、持仓看原币”和“强制切到某个货币后全都统一”的双重需求。
- 备选：
  - 只做“统一目标币种”模式，不保留 `default` 特例。实现更简单，但不能满足默认视图需求。
  - 后端按查询参数返回不同币种快照。会放大接口复杂度，而且现有数据已经足够前端实时换算，因此不采用。

### 2. 统一用 CNY 作为中间基准做跨币种换算

- 决策：
  - 汇总级金额（总资产、类别金额、类别盈亏、再平衡金额）从 CNY 基准值换到目标币种。
  - 持仓级金额优先从原币金额换到目标币种；若目标为 `CNY`，直接复用现有 `*Cny` 字段。
  - 收益率、占比、偏离度不重新计算币种，直接复用现有百分比字段。
- 理由：现有汇率表只保证 `XXX/CNY`，以 CNY 为中间层可以覆盖 CNY、USD、HKD 间互转，且不会引入额外汇率持久化。
- 备选：
  - 为每种账户币种之间维护完整交叉汇率。数据冗余，且没有必要。
  - 所有金额都先回退到原币再按 pair 转换。对类别汇总与总资产不可行，因为这两个值本来就只有 CNY 汇总口径。

### 3. 持仓展示抽成显式的 display mode，而不是继续内嵌“外币补一个 ≈¥”

- 决策：`HoldingRow` 接收显式显示模式和目标货币，统一计算“当前应该展示的金额和盈亏金额”；账户页传入默认模式，纪律表根据 Dashboard 选择传入默认或目标货币模式。现金行在纪律表中沿用同一规则。
- 理由：现在“原币 + ≈¥”的分支散落在账户页和纪律表里，后续再支持更多币种时会继续膨胀；抽成 display mode 能让默认与强制货币视图共享同一套渲染逻辑。
- 备选：只在 Dashboard 里做字符串替换，账户页保留旧逻辑。这样会让两个页面再次分叉，不符合用户要求。

### 4. 通用交易入口复用现有 `TransactionForm`，但默认值语义拆成“有上下文”和“无上下文”

- 决策：
  - `TransactionForm` 继续接受 `defaultType/defaultAccountId/defaultHoldingId`。
  - 当 `defaultAccountId/defaultHoldingId` 未传入时，不再自动选中第一个账户，也不预选持仓。
  - 当从持仓快捷入口打开时，仍显式传入账户和持仓，保持原有预填与价格联动行为。
- 理由：这能最小化改动现有交易流程，同时满足 Dashboard 通用交易入口和交易页“新增交易”的空上下文需求。
- 备选：新增一个独立的“轻量交易表单”组件。会重复表单逻辑和副作用开关，不值得。

## Risks / Trade-offs

- [Risk] 默认视图与显式 `CNY` 视图只有持仓明细不同，用户可能一开始不易感知差异 -> Mitigation：下拉选项文案明确保留“默认”，并让默认/CNY 选中后卡片标题与持仓金额表现存在可预期差异。
- [Risk] 跨币种换算依赖 `XXX/CNY` 汇率，若缺失某个 pair 会出现回退值 -> Mitigation：复用现有汇率回退策略，缺失时保守按 1 处理并继续展示，不阻塞页面。
- [Risk] Dashboard 顶层新增交易按钮后会引入额外的 accounts/holdings 查询 -> Mitigation：继续使用现有 Query Cache；与纪律表内部查询共享同一缓存键，不增加新的后端契约。
- [Risk] 图表、纪律表、再平衡分别各自做货币换算，容易出现口径不一致 -> Mitigation：抽出共享货币投影辅助函数，所有展示层都通过同一转换入口取值。

## Migration Plan

1. 先补充前端货币投影辅助函数和类型，确保 CNY/原币/目标币种三种读取方式统一。
2. 调整 `TransactionForm` 默认值策略，并在 Dashboard 纪律区接入新的通用交易按钮。
3. 改造纪律表、持仓行、再平衡建议、总资产卡片和饼图，使它们消费同一 display mode。
4. 同步更新 OpenSpec 主 specs、`project_overview.md` 和项目文档摘要。

**Rollback**

- 若货币切换展示出现问题，可先移除 Dashboard 下拉框并让组件回退到默认显示模式；底层资产计算与交易写入逻辑不会受影响。
