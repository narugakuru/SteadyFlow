## Why

当前投资笔记弹窗在阅读/编辑模式之间会明显跳动：阅读模式高度过大但可滚动区域不稳定，编辑模式又被压缩得过窄，导致用户切换模式时持续失去空间感。与此同时，手动或自动股价更新链路没有顺带刷新汇率，跨币种资产汇总可能继续基于过期汇率计算，影响总资产与纪律判断的可信度。

## What Changes

- 统一投资笔记弹窗在阅读模式与编辑模式下的尺寸约束：桌面端保持同一套大尺寸弹窗，移动端改为占满可视区域的全屏式布局。
- 调整笔记内容区域的滚动职责，将进度条与外层弹窗固定，只有正文文本区域滚动，避免整个弹窗内容随滚动一起位移。
- 去除笔记编辑模式的显式“保存”按钮，改为编辑区域失去焦点后自动保存，并保持 Markdown 阅读/编辑切换顺滑稳定。
- 扩展 `POST /api/holdings/fetch-prices` 及其复用的静默/Cron 报价同步链路，在执行股价刷新时同步刷新汇率缓存，确保后续资产换算使用同一轮最新汇率。
- 保持现有页面入口、数据隔离和报价同步主流程不变，避免对既有能力引入额外操作步骤。

## Capabilities

### New Capabilities

- 无

### Modified Capabilities

- `discipline-notes`: 补充笔记中心弹窗在阅读/编辑模式下的统一尺寸、移动端全屏占位、正文内部滚动与失焦自动保存要求。
- `auto-quote-fetch`: 补充手动、静默与 Cron 报价同步在同一链路中联动汇率刷新的要求。
- `exchange-rate`: 补充汇率刷新被报价同步链路复用时的缓存、降级与一致性约束。

## Impact

- 前端：投资笔记弹窗布局、编辑器容器滚动、保存交互、移动端弹窗适配。
- 后端/API：`POST /api/holdings/fetch-prices` 的同步流程、Cron 复用报价刷新链路、汇率服务调用顺序与失败降级处理。
- 数据与测试：笔记自动保存回归、弹窗滚动与尺寸回归、跨币种持仓在报价同步后使用最新汇率的回归验证。
