## Context

当前 Dashboard 纪律表的资产类别顺序来自资产类别默认排序，展开后的持仓明细顺序来自 `disciplineSortOrder`。这满足“手动编排类别内顺序”的长期语义，但缺少临时比较视图。新需求要求用户能快速按金额或持仓盈亏查看每个类别里的重点仓位，同时明确禁止打乱“股票、黄金、债券、现金”等大类顺序。

该改动主要影响 Dashboard 前端渲染与本地状态，不需要后端新增接口；但需要同时覆盖桌面表格和移动端卡片，且保证与既有拖拽排序语义不冲突。

## Goals / Non-Goals

**Goals:**

- 为纪律表展开明细提供金额/持仓盈亏的三态临时排序。
- 让排序只在单个资产类别内部生效，资产类别顶层顺序保持数据库默认值。
- 将排序偏好存储到本地，使刷新后仍保留同一视图。
- 为桌面端和移动端提供明确、一致的排序状态反馈。

**Non-Goals:**

- 不改动资产类别默认顺序，也不新增资产类别级别的临时排序。
- 不改动 `disciplineSortOrder` 的持久化拖拽逻辑；本次排序不写回数据库。
- 不实现多字段联合排序、URL 分享排序状态，或按账户等额外字段排序。

## Decisions

### 1) 排序状态采用单一全局偏好，应用到所有类别内明细

- 决策：在客户端维护 `{ key, direction } | null` 的纪律表排序偏好；点击“金额”或“持仓盈亏”时按 `desc -> asc -> default` 循环，并对每个资产类别的明细列表分别执行同一排序规则。
- 原因：PRD 要求排序字段与方向持久化到本地，同时强调“层级锁定”。单一偏好可以保证桌面表头与移动端 helper 行状态一致，也避免用户在不同类别看到不一致的排序语义。
- 备选：为每个类别维护独立排序偏好；交互更复杂，且与“表头统一控制”的设计不符，因此不采用。

### 2) 排序比较统一使用折算后的同一货币基准

- 决策：金额排序使用 `marketValueCny`，持仓盈亏排序使用 `pnlAmountCny`；即先将不同账户币种折算到同一货币基准后再比较，而不是直接比较原币数字。
- 原因：纪律表同一类别下可能同时包含 CNY / USD / HKD 持仓，直接比较原币金额或盈亏会得到错误顺序；统一货币后才能满足“跨币种可比较”的要求。
- 备选：在默认视图下直接按原币金额比较，或按当前显示币种临时换算；前者错误，后者和统一基准在排序结果上等价但实现更分散，因此不采用。

### 3) 默认态直接回退到后端返回的 `disciplineSortOrder`

- 决策：仅在前端对 `item.holdings` 做临时复制排序；当排序状态为 `null` 时，保持 API 返回顺序不变。
- 原因：数据库中的 `disciplineSortOrder` 已经定义了类别内默认手动顺序，第三态“默认”必须无损回退到这个来源。
- 备选：在客户端重新根据 `disciplineSortOrder` 二次排序；虽然可行，但会重复实现后端已保证的默认顺序，不采用。

### 4) 本地持久化使用专用 localStorage 键

- 决策：新增纪律表排序状态读写辅助函数，统一序列化到浏览器 `localStorage`，仅保存允许的 `key` 与 `direction` 组合。
- 原因：需求要求刷新后保留偏好，但不写数据库；显式封装读写可以集中处理 SSR 安全和非法值兜底。
- 备选：内联写在组件里；实现更快，但会把解析、校验和默认值逻辑散落到 UI 层，不采用。

### 5) 桌面与移动端分别提供适配的排序控件，但共享同一状态

- 决策：桌面端在“金额 / 持仓盈亏”表头右侧增加 12px 双向箭头，并用蓝色高亮激活项；移动端在纪律卡片列表上方增加 sticky helper 行，展示两个可点击标签和激活圆点。
- 原因：桌面表格天然适合放在表头；移动端卡片缺少对齐参照，helper 行能在不改动卡片主体层级的前提下提供清晰控制。
- 备选：移动端继续使用按钮组；虽然实现简单，但与卡片金额列对齐关系弱，视觉指向性不够，不采用。

## Risks / Trade-offs

- [Risk] 现金类别的持仓盈亏恒为 `--`，按盈亏排序的反馈可能不明显 -> Mitigation: 仍允许复用同一排序状态，但在比较函数中让空盈亏回退到默认顺序。
- [Risk] 本地持久化的旧值或非法值可能导致 hydration 后状态异常 -> Mitigation: 通过专用解析函数白名单校验，仅接受支持的字段和方向。
- [Risk] 展开详情在排序切换时整体重排，可能让用户误以为影响了数据库顺序 -> Mitigation: 三态第三次点击恢复默认，并在文档/spec 中明确“仅为本地临时排序”。

## Migration Plan

1. 新增纪律表排序状态读写辅助函数，并在 `discipline-table` 中接入。
2. 为桌面表头和移动端 sticky helper 行增加排序交互与视觉状态。
3. 对每个资产类别内部的展开明细应用本地排序，默认态保持原始顺序。
4. 回归验证桌面/移动端三态循环、刷新后持久化、类别顺序不变。
