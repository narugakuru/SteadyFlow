## Why

当前移动端在批量更新页和多个弹窗场景仍存在可用性问题（布局崩坏、关闭按钮触控面积不足、弹窗高度超出屏幕），同时资产类别文案与排序在不同页面不一致，影响操作效率和认知一致性。该变更需要统一移动端交互与资产类别展示规范，降低误操作并提升日常维护体验。

## What Changes

- 删除各页面中冗余的“返回 Dashboard/总览”按钮，统一通过全局导航完成页面返回。
- 修复批量更新页在移动端的布局崩坏问题，确保输入区、操作区和列表在小屏下稳定可用。
- 统一移动端弹窗（交易、新增账户、编辑等）交互：关闭按钮触控面积增大、可见性增强，弹窗最大占据可视区域 100%，不出现超出手机屏幕的情况。
- 统一资产类别文案，将“股票基金”改为“股票”，覆盖纪律表、配置弹窗、相关下拉与展示文案。
- 统一资产配置纪律默认排序为：股票、黄金、债券、现金。

## Capabilities

### New Capabilities

- None

### Modified Capabilities

- `mobile-responsive`: 强化移动端弹窗边界与关闭操作可点击区域，确保弹窗不超出可视屏幕。
- `batch-update`: 明确批量更新页在移动端必须保持可读可操作的稳定布局。
- `asset-allocation`: 统一资产类别名称“股票基金”到“股票”，并固定默认展示顺序为“股票、黄金、债券、现金”。
- `navigation-layout`: 移除页面内冗余“返回总览”按钮，统一依赖全局导航进行页面切换。

## Impact

- 前端页面与组件：`src/app/batch-update/page.tsx`、各业务弹窗组件、资产类别配置与纪律表相关组件。
- 样式与交互：Dialog/Sheet/按钮尺寸与布局规则调整，移动端断点下样式重构。
- 数据与展示：资产类别名称兼容处理（旧文案映射为新文案）与默认排序规则统一。
- 测试与验收：需要补充移动端视口下的关键 UI 场景验证（批量更新、交易弹窗、账户弹窗、配置弹窗）。
