## Context

当前交易弹窗在切换交易类型时会重置持仓选择，导致用户需要重复选择；同时买卖交易未自动带出持仓价格，增加了录入成本。收益口径方面，系统仅将卖出交易计入 `realizedPnl`，导致股息收益未进入账户累计了结盈亏，和用户预期不一致。

## Goals / Non-Goals

**Goals:**

- 在交易弹窗内切换买入/卖出/股息时保留已选账户与持仓上下文。
- 在买入/卖出场景下，选中持仓后自动填充该持仓记录价格，并允许用户覆盖。
- 将股息交易纳入 `realizedPnl` 统计（受 `affectCash` 控制），并在账户累计中增量维护。
- 保持删除交易时的对称回退行为，无需新增删除分支。

**Non-Goals:**

- 不调整数据库 schema，不新增字段。
- 不变更现有持仓成本算法（shares/amount 模式均保持现状）。
- 不引入新的交易类型或新的副作用开关。

## Decisions

1. 交易弹窗状态初始化改为“仅在打开时初始化一次”，不在打开态随 props 变化全量重置。

- Rationale: 避免用户在弹窗内操作过程中因列表刷新或类型切换被动丢失已填内容。
- Alternative: 继续在依赖变化时重置并增加白名单字段保留。该方案复杂且容易遗漏。

2. 类型切换不再清空 `holdingId`，仅在账户切换时清空持仓。

- Rationale: 买入/卖出/股息属于同一交易上下文切换，账户与标的应保持一致；账户变化时持仓列表变化，清空是合理的。
- Alternative: 类型切换后按规则自动重选第一个持仓。该行为不可预期，且会覆盖用户意图。

3. 买入/卖出在持仓选中后自动填充价格，来源为 `holding.price`。

- Rationale: `holding.price` 已是系统内最新可用价格，作为默认成交价能显著降低手输成本。
- Alternative: 维持空值让用户手填。准确性高但操作成本高，不符合目标。

4. `realizedPnl` 规则扩展为：

- 卖出：`type=sell && affectHolding=true`（保持现有）；
- 股息：`type=dividend && affectCash=true`，`realizedPnl = amount - fee`。
- Rationale: 股息本质是已实现收益，且 `affectCash` 关闭时属于仅记录历史，不应改变收益累计。
- Alternative: 无条件将股息计入 realized。会与“仅记录不改资产”的开关语义冲突。

## Risks / Trade-offs

- [Risk] 自动填充价格可能与实际成交价不一致 → Mitigation: 保持输入框可编辑，自动填充仅作为默认值。
- [Risk] 打开态不再全量重置可能引入陈旧选项 → Mitigation: 仅同步持仓列表数据，不覆盖用户已选值；账户切换时仍清空持仓。
- [Risk] 收益口径变化影响历史对比 → Mitigation: 仅影响新写入股息交易；历史数据保持既有值，符合现有“增量维护”策略。
