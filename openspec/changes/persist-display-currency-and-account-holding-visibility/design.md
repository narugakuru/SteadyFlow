## Context

当前项目已经有一套 `DisplayCurrencyMode = default | CNY | USD | HKD` 的前端换算工具，但状态只保存在 `src/app/page.tsx` 的局部 `useState` 中。Dashboard 因此可以切换显示货币，账户页与交易页则继续展示原币金额，刷新页面后 Dashboard 也会回到默认值。另一方面，账户页持仓列表当前直接读取 `/api/holdings`，没有暴露“默认隐藏零市值持仓、按开关显式请求”这一交互层能力。

本次变更是一个横跨 Dashboard / Accounts / Transactions 的展示层调整，约束很明确：

- 显示货币状态只保存在浏览器本地，不进入云端数据库。
- “默认”代表显示记录原始币种，而不是统一换成 CNY。
- 非默认模式下，金额由前端基于原币和汇率实时换算，不保存额外字段。
- 账户页的“显示未持仓标的”默认关闭，并复用已有接口口径，不重写后端查询逻辑。

## Goals / Non-Goals

**Goals:**

- 把 Dashboard 的货币选择升级为全局共享、刷新后可恢复的本地状态。
- 让 Dashboard、账户页、交易页基于同一显示货币状态展示金额，并保持默认/指定货币两种口径一致。
- 在账户页新增“显示未持仓标的”开关，默认隐藏零市值持仓，开启后再显示。
- 复用现有汇率接口和持仓接口，不引入新的数据库字段或设置项。

**Non-Goals:**

- 不新增服务端用户设置，不把显示货币同步到 `settings` 表。
- 不改动净值、资产配置或交易写入的底层计算基准，它们仍以原有口径保存。
- 不为交易页新增独立货币切换器；交易页只消费 Dashboard 设定的全局显示货币。
- 不改动持仓/交易的业务副作用与数据库结构。

## Decisions

### 1. 用浏览器本地存储维护全局显示货币，而不是继续放在 Dashboard 局部状态

- 决策：新增一个轻量级客户端状态模块，统一提供“读本地存储初值 + 写回 localStorage + 页面间共享”的显示货币 hook。Dashboard 写入，Accounts / Transactions 读取并订阅。
- 理由：需求明确要求“主页的开关控制全局”且“状态持久化到本地”。把状态继续放在首页局部只会让其他页面无法复用，也无法在刷新后恢复。
- 备选：
  - 写入数据库 `settings`。放弃原因：需求明确排除云端存储。
  - 仅用 URL 参数跨页面传递。放弃原因：刷新后不稳，且不满足“全局开关”预期。

### 2. 默认模式与指定货币模式分开定义，避免误把默认视图改成 CNY 统一口径

- 决策：
  - `default`：所有页面均显示记录原始币种金额。
  - `CNY/USD/HKD`：所有页面按目标币种显示金额，使用前端实时换算。
- 理由：用户本次明确把“默认”定义为“显示记录的原始货币”，这比 3 月 change 中 Dashboard 的“默认=汇总 CNY、明细原币”更强，需要更新为全站统一语义。
- 备选：
  - 保留 Dashboard 旧语义，仅把账户页/交易页做成“默认原币”。放弃原因：会造成全局开关同名不同义。

### 3. 统一通过现有换算工具与汇率接口做展示投影，不在业务数据结构中新增转换字段

- 决策：
  - Dashboard 和账户页优先复用资产快照中的 `rates`。
  - 交易页单独读取 `/api/exchange-rates`，在渲染层把账户原币金额换算到目标币种。
  - 所有转换继续以 CNY 为中间基准，通过 `XXX/CNY` 汇率互转。
- 理由：仓库已经有稳定的汇率工具和接口，且需求明确要求“不存储额外数据”。
- 备选：
  - 后端为每个接口返回多币种金额。放弃原因：会扩大接口面且重复计算。

### 4. 账户页未持仓开关只影响账户明细列表，不影响账户汇总统计

- 决策：账户卡片上的总价值、现金、持仓盈亏、持仓数继续沿用 `/api/accounts` 的完整聚合结果；“显示未持仓标的”仅控制展开后持仓明细使用的 `/api/holdings` 查询参数和前端列表渲染。
- 理由：这符合“显示开关”而非“统计口径切换”，也能保持最小改动。
- 备选：
  - 让账户汇总统计也跟着排除零市值持仓。放弃原因：会改变既有账户数值口径，并可能引发与后端聚合不一致。

## Risks / Trade-offs

- [Risk] 从旧 Dashboard 默认语义切到“默认=原币”后，首页汇总金额会和过去不同 -> Mitigation：同步更新 Dashboard spec 和相关文档，确保行为变更被明确记录。
- [Risk] 交易页单独读取汇率接口，短时间内可能与 Dashboard 资产快照使用的汇率时间点略有不同 -> Mitigation：复用同一来源接口，且仅影响展示层，不影响底层数据。
- [Risk] `localStorage` 在部分环境不可用或数据损坏 -> Mitigation：读取失败时回退到 `default`，保持页面可用。
- [Risk] 账户页同时存在货币开关与未持仓开关，移动端顶部空间会更紧 -> Mitigation：沿用现有紧凑按钮/选择器尺寸，必要时允许换行但保持顺序不变。

## Migration Plan

1. 新增显示货币本地状态工具，并先接入 Dashboard 取代局部 `useState`。
2. 将账户页、交易页的金额展示接入同一状态；账户页同时改造持仓查询以支持“显示未持仓标的”。
3. 更新主 specs、`project_overview.md` 与必要的项目文档摘要，记录“默认语义变更”和新开关行为。
4. 运行 lint / typecheck 验证展示层改造。

**Rollback**

- 若全局状态实现出现问题，可先回退到 `default` 常量模式；不会影响数据库内容。
- 若账户页开关查询出现问题，可临时恢复到现有 `/api/holdings` 默认口径，账户汇总统计不受影响。

## Open Questions

- None. 当前需求已经明确：全局货币开关本地持久化、默认显示原币、账户页新增未持仓开关且默认关闭。
