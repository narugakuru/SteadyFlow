## ADDED Requirements

### Requirement: 报价同步元数据持久化

系统 SHALL 在每次报价同步开始与结束时，为当前用户持久化标准化的报价同步元数据。该元数据 MUST 至少记录最近一次开始时间、完成时间、成功时间、状态、触发来源以及摘要信息，并与持仓数据更新时间语义解耦。

#### Scenario: 手动更新股价写入元数据

- **WHEN** 用户通过手动“更新股价”触发一次报价同步
- **THEN** 系统在同步开始时写入最近开始时间与触发来源，在同步完成后写入完成时间、状态与摘要；若存在成功更新项，则同时写入最近成功时间

#### Scenario: 静默刷新写入元数据

- **WHEN** 页面以静默模式触发一次报价同步
- **THEN** 系统按与手动模式一致的口径更新报价同步元数据，并将触发来源记录为静默客户端刷新

#### Scenario: 每日 Cron 写入元数据

- **WHEN** 每日后台 Cron 链路执行报价同步
- **THEN** 系统按相同字段口径更新报价同步元数据，并将触发来源记录为 Cron

### Requirement: 报价同步元数据可标准化读取

系统 SHALL 将用户级报价同步元数据标准化为统一对象，以供 Dashboard 与导出接口消费。即使用户从未进行过报价同步，系统也 MUST 返回结构完整的默认对象，而不是返回不透明的原始键值集合。

#### Scenario: Dashboard 读取标准化状态

- **WHEN** Dashboard 需要展示股价上次更新时间
- **THEN** 系统向页面提供标准化的 `quoteSync` 对象，而不是暴露底层 `settings` 键列表

#### Scenario: 导出接口读取标准化状态

- **WHEN** 导出接口返回投资组合快照
- **THEN** 快照中的 `meta.quoteSync` 使用与页面一致的标准化字段命名与语义

#### Scenario: 从未同步时的默认状态

- **WHEN** 用户没有任何报价同步记录
- **THEN** 系统返回结构完整且字段可预期的默认 `quoteSync` 对象，其中未产生值的时间字段为 `null`
