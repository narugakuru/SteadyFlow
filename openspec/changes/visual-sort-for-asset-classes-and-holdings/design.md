## Context

当前资产类别已具备后端 `sortOrder` 能力，但缺少可视化入口；持仓（标的）尚无持久化排序字段与管理交互。用户希望在日常页面中直接调整类别和标的显示顺序，并在刷新、跨页面、跨会话后保持一致。

该需求跨越数据层（schema/迁移）、API 层（读取与写入排序）、前端层（排序操作交互与状态回写），属于典型的跨模块改造。
同时，交易页面需改为稳定的横向表格信息架构，并统一删除按钮视觉语言，减少页面间交互风格差异。

## Goals / Non-Goals

**Goals:**

- 在资产配置设置页提供类别可视化排序，并持久化到数据库。
- 在持仓列表（账户页、纪律表展开区）提供标的可视化排序，并持久化。
- 保证所有依赖同一数据源的展示入口读取一致顺序。
- 新增/删除条目后顺序规则稳定、可预期。
- 将交易页面改为横向表格布局，并统一列顺序和删除按钮样式。

**Non-Goals:**

- 本次不引入复杂拖拽动画与多端实时协同排序冲突解决。
- 本次不实现跨账户共享同一标的排序（持仓排序以账户内为主）。
- 不变更现有资产配置计算公式与交易副作用逻辑。
- 不改变交易创建/删除的数据语义，仅调整交易列表展示与操作样式。

## Decisions

### 1) 交互方案采用“上移/下移”优先

- 决策：资产类别与持仓排序先使用上移/下移按钮实现可视化排序。
- 原因：无需新增依赖，移动端可用性更稳定，开发和回归成本低。
- 备选：拖拽排序（如 dnd-kit）交互更直观，但引入额外复杂度和移动端边界问题。

### 2) 排序持久化采用显式 `sortOrder` 字段

- 决策：资产类别继续使用 `asset_classes.sort_order`；持仓新增 `holdings.sort_order`。
- 原因：查询简单（`orderBy sortOrder`），兼容现有 API，易于回填历史数据。
- 备选：独立排序映射表（更灵活但增加 join/维护复杂度）。

### 3) API 采用批量提交排序结果

- 决策：排序变更通过批量 payload 更新（包含 `id` + `sortOrder`），一次提交完成。
- 原因：减少请求次数，避免逐条更新导致的中间态闪烁。
- 备选：逐条交换排序值，接口简单但并发与一致性更差。

### 4) 查询层统一显式排序

- 决策：所有类别/持仓读取接口统一 `orderBy(sortOrder, id)`。
- 原因：杜绝数据库默认返回顺序不稳定的问题。
- 备选：前端排序兜底；会造成逻辑分散且多端不一致。

### 5) 历史数据回填与兼容策略

- 决策：迁移时为历史记录补齐 `sortOrder`；默认类优先顺序固定为 股票/黄金/债券/现金，历史“股票基金”并入股票优先级；其余按 `1000 + id`。
- 原因：确保旧库升级后立即有稳定顺序，避免空值或随机顺序。

### 6) 交易列表采用固定字段顺序的横向表格

- 决策：交易页面列表统一为横向表格，列顺序固定为：账户、标的名称、操作类型、股数、股价、金额、手续费、日期；删除操作使用小垃圾桶图标按钮（与账户页一致）。
- 原因：信息密度更高、对比更直接，且跨页面操作视觉更统一。
- 备选：继续使用卡片或松散列表；在交易记录量增大时扫描效率较低。

## Risks / Trade-offs

- [Risk] 批量排序更新与目标占比保存耦合，可能互相覆盖 -> Mitigation: 拆分或扩展现有接口，明确字段语义与幂等行为。
- [Risk] 持仓排序按账户维度定义，跨账户查看可能有认知差异 -> Mitigation: 在交互文案中明确“当前账户内排序”。
- [Risk] 大量持仓时频繁上移/下移操作效率一般 -> Mitigation: 先保证稳定可用，后续可再演进拖拽模式。
- [Risk] 历史数据回填规则与个别用户习惯不一致 -> Mitigation: 提供可视化重排入口，允许用户自行调整并保存。
- [Risk] 交易表格在小屏可能出现可读性压力 -> Mitigation: 保留横向滚动容器与最小列宽，确保字段不折叠错位。

## Migration Plan

1. 为 `holdings` 增加 `sort_order` 字段（SQLite/PG 双迁移）。
2. 迁移脚本回填历史排序值（按账户内 `id` 或业务规则顺序）。
3. API 查询统一按 `sortOrder,id` 返回。
4. 增加排序更新接口/字段，前端接入上移下移并回写。
5. 灰度验证关键页面（账户页、纪律表、设置页）后全量上线。
6. 验证交易页面表格列顺序、数值显示与删除按钮样式一致性。

## Open Questions

- 持仓排序是否需要同时支持“按资产类别分组内排序”与“账户全局排序”双模式？
- 排序保存是否与目标占比保存共用一个“保存”按钮，还是分离为独立操作？
- 后续是否规划拖拽增强版（桌面拖拽 + 移动端长按排序）作为 P3？
- 交易页面在移动端是否仅保留横向滚动表格，还是需要额外的紧凑视图切换？
