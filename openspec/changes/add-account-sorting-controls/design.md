## Context

当前账户页只支持账户内持仓排序，不支持账户自身的默认顺序管理；列表顺序依赖数据库返回结果，刷新后也无法保证符合用户偏好。与此同时，用户还希望像表格一样快速按总价值、持仓盈亏、现金、持仓数进行高低比较，但这种比较排序不应覆盖长期保存的账户默认顺序。

该改动会同时影响账户数据模型、账户 API、账户页组件与移动端/桌面端排序一致性，且需要兼容历史账户数据，因此需要先明确默认排序与临时排序的边界。

## Goals / Non-Goals

**Goals:**

- 为账户页提供可持久化的账户默认排序能力，并在刷新后保持稳定。
- 为账户页提供“总价值 / 持仓盈亏 / 现金 / 持仓数”的三态临时排序能力。
- 保证桌面表格与移动端卡片共用同一套排序状态与结果。
- 让临时列排序可以随时恢复到用户保存的默认账户顺序。

**Non-Goals:**

- 不改造账户内持仓排序逻辑，现有 `holdings.accountSortOrder` 继续只负责账户内持仓顺序。
- 不实现多列联合排序或自定义排序规则保存。
- 不处理跨用户协同排序冲突，仍按单用户个人工具场景设计。

## Decisions

### 1) 为账户新增独立默认排序字段

- 决策：在 `accounts` 表新增 `sort_order`（前端类型映射为 `sortOrder`），作为账户默认排序字段；账户列表默认按 `sort_order ASC, id ASC` 返回。
- 原因：用户要求“第三次点击恢复默认排序”，这需要一个稳定且可持久化的账户级顺序来源，不能复用当前无语义保证的数据库自然顺序。
- 备选：仅使用前端本地状态保存默认顺序；多端/刷新后不稳定，不采用。

### 2) 手动账户排序使用专用重排接口

- 决策：新增 `POST /api/accounts/reorder`，接收完整账户 `id` 列表并批量写回 `sort_order`；服务端校验账户归属且要求提交当前用户全部账户。
- 原因：账户排序与持仓排序属于不同实体，复用 `holdings/reorder` 会让接口语义变得含混，也更容易误写字段。
- 备选：扩展现有重排接口增加 `scope=account`；可行但会把账户与持仓的校验逻辑强行耦合，当前不采用。

### 3) 表头排序仅作为前端临时覆盖层

- 决策：账户页在客户端维护单一排序状态 `{ key, direction }`，点击“总价值 / 持仓盈亏 / 现金 / 持仓数”时按 `desc -> asc -> default` 循环；`default` 直接回退到服务端返回的默认账户顺序。
- 原因：列排序是临时比较视图，不应覆盖用户保存的账户默认顺序；前端覆盖实现简单，也避免增加不必要的后端状态。
- 备选：把列排序参数写入 URL 或数据库；当前需求没有分享/记忆列排序的要求，不采用。

### 4) 账户排序弹窗独立实现，但复用现有拖拽基础设施

- 决策：新增 `AccountSortDialog`，复用现有 `@dnd-kit` 方案与移动端拖拽约束辅助函数，提供全账户范围的拖拽排序。
- 原因：账户排序展示字段与文案和持仓排序不同，单独组件更容易保持实现清晰；同时继续复用现有触摸/鼠标传感器与纵向拖拽约束，降低移动端回归风险。
- 备选：把 `HoldingSortDialog` 直接泛化为通用组件；当前改动范围更大，且容易在现有持仓排序场景引入回归，不采用。

### 5) 新建账户默认追加到末尾

- 决策：创建账户时读取当前用户最大 `sort_order`，新账户默认写入末尾顺序。
- 原因：符合手动排序的一致预期，也避免新增账户打乱已有默认顺序。
- 备选：统一默认值 `999` 再依赖查询次序兜底；排序稳定性差，不采用。

## Risks / Trade-offs

- [Risk] 历史账户没有 `sort_order` 时会出现默认顺序漂移 → Mitigation: 迁移时按当前稳定顺序（`created_at, id` 或 `id`）回填，并在查询中保留 `id` 兜底。
- [Risk] 临时列排序与手动排序并存可能让用户混淆“当前看到的顺序”和“保存的默认顺序” → Mitigation: 将表头排序做成显式三态，第三次点击清空；排序弹窗始终基于默认顺序打开。
- [Risk] 移动端拖拽账户排序可能重复出现触摸被滚动抢占的问题 → Mitigation: 继续复用现有移动端拖拽约束与句柄接管策略。

## Migration Plan

1. 为 SQLite / PostgreSQL 的 `accounts` 表新增 `sort_order` 字段，并为历史账户回填稳定顺序。
2. 调整账户查询与创建逻辑，默认读写 `sort_order`。
3. 新增账户重排接口与账户排序弹窗。
4. 在账户页接入手动排序按钮与表头三态排序。
5. 回归验证：默认顺序保存、列排序三态循环、移动端/桌面端一致、刷新后默认顺序保持。

## Open Questions
