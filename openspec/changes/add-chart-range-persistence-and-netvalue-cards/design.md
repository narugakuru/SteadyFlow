## Context

总览页当前通过 `OverviewAssetTrend` 展示资产趋势图，范围状态由 `src/app/page.tsx` 内存态控制，刷新后回到默认值。净值页通过 `NetvalueCharts` 展示总资产折线图和资产类别占比堆叠面积图，数据接口已支持按固定 range 聚合，但默认范围和视觉风格与总览页不一致。

本次变更只调整净值历史图表的区间枚举、前端偏好状态和图表呈现，不改数据库结构，不新增依赖。

## Goals / Non-Goals

**Goals:**

- 为净值图表范围增加 `7d`，并保持 `7d/30d/90d/1y/3y/all` 在总览与净值页一致可用。
- 总览资产趋势图默认选中 `30d`，并通过浏览器本地存储恢复用户最近选择。
- 净值页图表改为与总览一致的浅色卡片风格，弱化坐标轴，仅在底部保留日期。
- 总资产走势图隐藏明显数据点，保留 Tooltip 悬停读数。

**Non-Goals:**

- 不调整净值计算、净值快照持久化结构或列表分页逻辑。
- 不新增图表库、设计系统或后端缓存层。
- 不把图表范围偏好同步到数据库或跨设备。

## Decisions

1. 扩展现有 `NetvalueChartRange` 联合类型和 `NETVALUE_CHART_RANGE_ORDER`。

   理由：前端和 API 已通过统一类型校验 range，扩展现有枚举可以让总览、净值页与 API 保持同一契约。`7d` 使用 `day` 粒度，服务端起始日期按 7 天窗口计算。

   备选：只在总览页做前端过滤。该方案会让 API range 和缓存 key 语义不一致，也无法复用净值页图表接口。

2. 总览图表范围偏好使用独立 localStorage key。

   理由：需求明确为本地缓存持久化，不需要用户级数据库设置。独立 key 可避免和现有显示货币、纪律表排序偏好耦合。

   备选：复用 TanStack Query 持久化缓存。该缓存面向服务端查询结果，和 UI 控件偏好生命周期不同，不适合作为控件状态来源。

3. 净值页继续复用 `GET /api/netvalue/chart` 响应，只改组件呈现。

   理由：当前接口已同时返回总资产点和资产类别占比点，需求主要是视觉调整；复用接口可避免后端行为扩大。

   备选：拆两个专用组件或接口。当前没有数据契约差异，拆分会增加维护成本。

## Risks / Trade-offs

- [Risk] localStorage 在服务端渲染阶段不可用，可能导致默认值与客户端恢复值短暂不一致 → Mitigation：初始状态使用 `30d`，挂载后再读取有效本地值并更新。
- [Risk] 隐藏 Y 轴会降低精确读数能力 → Mitigation：保留 Tooltip 金额/百分比格式化展示。
- [Risk] `7d` 数据点过少时图表空态更常见 → Mitigation：沿用现有少于 2 点不绘图的规则，避免误导性趋势线。
